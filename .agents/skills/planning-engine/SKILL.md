# Planning Engine

## When to Apply
Use when breaking down complex features, planning sprints, estimating effort, or managing multi-step implementations. Apply before starting significant work or when tasks have interdependencies.

## Core Concepts
- **Work Breakdown Structure (WBS)**: Hierarchical decomposition of work
- **Dependency mapping**: Identifying task prerequisites and blockers
- **Critical path**: Identifying the longest sequence of dependent tasks
- **Effort estimation**: Comparing against reference implementations
- **Risk assessment**: Identifying potential blockers early
- **Milestone definition**: Creating measurable progress checkpoints

## Implementation
```
1. Define the end goal and success criteria
2. Decompose into major work components
3. Break components into discrete, estimable tasks
4. Map dependencies between tasks
5. Identify critical path and parallelizable work
6. Assign time estimates based on complexity
7. Define checkpoints for validation
```

## Best Practices
- Keep tasks small enough to complete in one session (1-4 hours)
- Identify blockers early and plan around them
- Add buffer time for unexpected complexity
- Validate plan against similar past projects
- Revisit and adjust plan as new information emerges

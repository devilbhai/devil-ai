# Sprint Planning

## When to Apply
Use this skill for agile development, sprint planning, backlog management, or team ceremonies.

## Core Concepts
- Sprint planning
- Backlog grooming
- Story points estimation
- Sprint goals
- Retrospectives
- Daily standups

## Best Practices
- Keep sprints consistent (1-2 weeks)
- Define clear sprint goals
- Limit work in progress
- Include all team members
- Time-box ceremonies
- Continuously improve

## Sprint Planning Meeting
```markdown
## Sprint 24 Planning

### Sprint Goal
Complete user authentication feature

### Stories
1. [8 points] Implement login API
2. [5 points] Create login UI
3. [3 points] Add password reset
4. [2 points] Write tests

### Capacity
- Team velocity: 18 points
- Available days: 10
- Holidays: 1

### Risks
- API documentation delayed
- Design review pending
```

## Story Points
- 1 point: Trivial
- 2 points: Small
- 3 points: Medium
- 5 points: Large
- 8 points: Very large
- 13 points: Epic (break down)

## Retrospective Format
```markdown
## Retrospective

### What went well?
- Good communication
- Met sprint goal
- Clean code

### What could improve?
- Better estimation
- More testing
- Earlier code review

### Action items
1. Add estimation game next sprint
2. Increase test coverage to 80%
3. Review code within 24 hours
```

## Daily Standup
```markdown
## Daily Standup - [Date]

### Yesterday
- Completed login API
- Started password reset

### Today
- Finish password reset
- Start UI tests

### Blockers
- Waiting for design review
```
